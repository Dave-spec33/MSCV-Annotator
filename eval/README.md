# Comparison evaluation

This directory reproduces inference and text-quality evaluation for three
systems on the same 1,488-sample held-out validation split:

1. Qwen3-VL-8B-Instruct without fine-tuning.
2. Qwen3-VL-8B-Instruct with the released QLoRA adapter.
3. Qwen3-VL-Plus through the DashScope OpenAI-compatible API.

Prediction files and per-sample evaluation records contain dataset-derived
text, so `eval/outputs/` and `eval/results/` are intentionally ignored by Git.
Only aggregate metrics are published in `eval/results.json`.

## Environment

Use the same MS-SWIFT, PyTorch, CUDA, Transformers, and bitsandbytes environment
as training, then install the evaluation-specific packages:

```bash
python -m pip install -r eval/requirements.txt
```

The commands below assume that
`portable_dataset/runtime_data/val.jsonl` has already been generated by the
path resolver and contains 1,488 rows.

## Local base and QLoRA inference

Run both local models with identical decoding and media limits:

```bash
MODEL_PATH=/root/autodl-tmp/models/Qwen3-VL-8B-Instruct \
ADAPTER_PATH=/path/to/qwen3vl8b-qlora-checkpoint \
VAL_DATASET=/root/autodl-tmp/cv_annotator/portable_dataset/runtime_data/val.jsonl \
bash eval/infer_compare.sh both
```

Use `base` or `lora` instead of `both` to run only one system. The script
uses greedy decoding (`temperature=0`), `max_new_tokens=128`, no validation
shuffle, and the same image/video token limits used during training.

## Qwen3-VL-Plus API inference

Set the API key through the environment; never place it in a source file:

```bash
export DASHSCOPE_API_KEY="your-api-key"
python eval/infer_qwen3vl_plus_api.py \
  --dataset portable_dataset/runtime_data/val.jsonl \
  --output eval/outputs/qwen3vl_plus_api.jsonl
```

The API script sends only the system prompt, user prompt, images, and sampled
video frames. It does not send the assistant reference. Results are appended
one row at a time and resume automatically after interruption. Use
`--no-resume` to restart or `--max-samples 10` for a small API test.

The alias `qwen3-vl-plus` is a managed API model and may be updated by the
provider. Exact future reproduction therefore also requires recording the API
model snapshot or invocation date when the provider exposes that information.

## Metric evaluation

The reported run used a local RoBERTa-large model with 24 layers:

```bash
python eval/evaluate_one.py \
  --prediction eval/outputs/qwen3vl8b_base.jsonl \
  --model-name qwen3vl8b_base \
  --bert-model /root/models/roberta-large

python eval/evaluate_one.py \
  --prediction eval/outputs/qwen3vl8b_qlora.jsonl \
  --model-name qwen3vl8b_qlora \
  --bert-model /root/models/roberta-large

python eval/evaluate_one.py \
  --prediction eval/outputs/qwen3vl_plus_api.jsonl \
  --model-name qwen3vl_plus_api \
  --bert-model /root/models/roberta-large
```

Each prediction row is paired with the validation reference at the same row
index. The evaluator rejects mismatched row counts and checks explicit
`index` fields when present.

### BERTScore

BERTScore precision, recall, and F1 use:

- RoBERTa-large with `num_layers=24`.
- English mode with `idf=False`.
- `rescale_with_baseline=False`.
- Batch size 32 on CUDA by default.

Because baseline rescaling is disabled, these absolute values should not be
compared directly with publications that enable rescaling or use another
encoder.

### Format success

A response passes when all of the following hold:

- It is non-empty.
- It contains no more than 80 English word tokens.
- It contains no more than two sentences.
- It contains no CJK characters and is not JSON-like.
- It does not mention bounding boxes, coordinates, masks, segmentation masks,
  or track IDs.
- It does not emit a parenthesized two- or four-number coordinate tuple.

## Reported results

| Model | BERTScore-P | BERTScore-R | BERTScore-F1 | Format success |
| --- | ---: | ---: | ---: | ---: |
| Qwen3-VL-Plus | 0.9700 | 0.9779 | 0.9740 | 0.9892 (1472/1488) |
| Qwen3-VL-8B-Instruct | 0.9660 | 0.9779 | 0.9719 | 0.9940 (1479/1488) |
| Qwen3-VL-8B-Instruct + QLoRA | **0.9857** | **0.9842** | **0.9850** | **0.9993 (1487/1488)** |

These metrics measure semantic similarity to the source text and compliance
with the requested output format. They do not independently measure grounding,
tracking, localization, hallucination, or human preference quality.
